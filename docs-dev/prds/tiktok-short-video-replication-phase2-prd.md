## 1. 产品目标与范围

对上游主代表帧及必要补充编辑锚点进行新场景替换，同时满足以下要求：

1. 保持原场景所需的功能与空间逻辑。
2. 新环境与原环境有显著视觉差异。
3. 同一物理场景内，不同机位及非连续出现的画面保持主要结构与外观一致。
4. 产品与人物保持原有形态、姿态、位置及核心区域的原色、原亮度。
5. 通过自检、定向返工和版本管理，形成可追溯的场景替换视觉锚点包。

首版包含物理场景分组、空间约束整理、方向设计、样图确认、整组扩展、主体保护、图片编辑、自检返工和版本交付。

审核通过聊天、对比图、联系表和结构化记录完成。本期不建设专用编辑 UI，不进行严格三维重建，不执行人物身份替换、视频生成、音频处理或最终拼接。

主体原色与原亮度、必要功能空间及显著环境差异是验收要求。分割或编辑能力不足时保留待处理结果，不通过放宽硬要求来宣称任务完成。

## 2. 核心概念、输入与流程

### 2.1 核心概念

| 概念 | 定义 |
| --- | --- |
| 物理场景 | 根据环境身份及空间关系识别的同一实际环境，可跨时间上不连续的片段 |
| 相邻场景组 | 第一阶段用于相邻片段关系和重组的分组，仅作为物理场景识别依据之一 |
| 原代表帧 | 上游选出的原始画面，提供主体、构图、功能、透视与采光证据 |
| 场景主参考图 | 经自检与用户确认的新场景样图，固定新环境外观和主要空间关系 |
| 补充视角参考 | 为主参考未充分表达的重要区域或机位关系建立的新场景参考 |
| 编辑锚点 | 主代表帧或被明确指定的补充编辑画面，必须保留对应源时间 |
| 观察帧 | 仅供理解空间、动作或遮挡的原画面，不自动进入编辑或下游生成队列 |
| 逻辑编辑任务 | 对一个明确锚点实施一个已批准编辑目标的任务，承载候选、返工计数及结果历史 |

### 2.2 输入

固定读取第一阶段指定修订中的源文件信息、原帧与工作基准、原子片段及生成片段关系、真实 PTS、时间区间和选帧审核状态。必要时读取源片段及观察帧，补充空间与操作依据。

每个原子片段默认使用一张主代表帧，不要求位于起点。补充编辑锚点须有明确用途。第二阶段发现覆盖缺口时可请求上游补证或增加锚点，角色和时间绑定应通过新的上游选择记录保存。

### 2.3 场景处理流程

**读取指定修订 → 识别物理场景 → 联合分析原帧与观察证据 → 提供两个文字方向 → 用户选择 → 准备并检查保护范围 → 制作样图、检查构图对应并合成 → 自检与用户确认 → 按需验证困难视角 → 扩展同场景图片 → 联合自检和返工 → 场景组确认与交付。**

不同场景可以独立推进。共享参考尚未通过检查时，不将其作为已确认参考继续扩展依赖图片。补充视角参考仍须遵循同一设计，不形成逐张继承误差的参考链。

## 3. 功能需求

### SR-001 固定输入与物理场景分组

每次处理固定消费第一阶段的具体修订，记录源视频、原帧、PTS、片段关联及素材哈希。场景替换不得改变源时间轴、剪辑边界、片段顺序或音频区间。

物理场景分组以环境身份和空间关系为依据，允许关联时间上不连续的同一环境，例如“厨房 → 院子 → 同一厨房”。不能因产品或人物相同直接认定同场景。

第一阶段相邻场景组不能直接等同于本阶段物理场景分组。关系不明确时先补充观察证据，仍无法确定则记录待确认。

上游出现新修订时，对照实际输入变化，不自动混用不同修订的图片和清单。

### SR-002 空间与功能约束

设计新场景前，联合查看该物理场景中的原关键帧，形成共享约束和每帧差异，至少覆盖：

- 同等级产品操作空间。
- 必要置物与承载平面，包括接触位置。
- 人物活动范围及操作所需通道。
- 相似机位、透视及遮挡条件。
- 同等级自然采光条件，以及与原主体相容的光照方向和明暗关系。
- 原关键帧及相关动作需要的其他功能性空间。

依据原画面中的可见比例、接触位置和动作范围判断，不臆测无法观察的精确物理尺寸。

允许替换为功能等价的其他环境类型。承载面外观可以变化，但必要的接触、承载与操作关系必须成立。远景重构也不得占用动作需要的空间。

### SR-003 显著视觉差异

每个设计方向须说明主要环境差异，并在结果中实际体现，例如材质体系、陈设布局、空间形态或远景结构变化。

仅轻微调色或增加少量摆件不能视为完成显著场景替换。与产品展现无关的远景允许结构性重构。

差异性依据已选方向中的可见环境变化检查，不用全图像素差异率替代判断，也不因主体保持不变而误判环境差异不足。

视觉变化不能以损害功能空间、主体保护或同场景一致性为代价。

### SR-004 主体保持与区域划分

产品和人物的外形、比例、位置、姿态及原有可见关系保持不变。图片编辑前区分以下区域：

| 区域 | 处理要求 |
| --- | --- |
| 核心保护区 | 可靠的不透明主体区域；保留原像素、原色、原亮度，以及文字、控制件等细节 |
| 光学适配区 | 允许对必要的边缘、透明透射、环境反射和接触阴影进行适配 |
| 环境编辑区 | 按场景方案替换背景及允许变化的环境表面 |

不能仅通过轮廓内缩确定核心区。把手孔洞、透明玻璃与金属环境反射分别处理；远离轮廓的主体中央也可能含旧环境反射。

保护范围须覆盖必要部件、标识、接缝、控制件和人物细节。不得为通过像素检查而缩小保护范围，也不能随意把关键纹理划入可重绘区。

保持原有可见遮挡顺序，不把所有主体简单叠放到最前方，不补造原图不可见的主体结构。

### SR-005 保护范围生成、修正与检查

分割模型暂不锁定。先约定其能力边界：输入原帧，输出候选主体范围及不确定区域；候选结果不能直接视为最终保护范围，也不默认具有产品、人物及配件的准确实例区分能力。

首版必须具备以下能力：

1. 展示原图与保护范围叠加结果，并提供边缘、孔洞和关键部件的局部视图。
2. 接收明确的区域修正或已修正掩膜，记录对应原帧、修改范围、理由和版本。
3. 修正后重新检查主体覆盖、区域归类和遮挡关系。
4. 无法可靠修正时保留待处理状态，并提供具体证据。

Agent 自动检查并尝试使用可用修正工具处理；未解决的歧义交由用户判断。接受明确修正结果导入不要求建设专用 UI，也不意味着将修正工作默认全部转交用户。

模型未选定、未有可用修正途径或保护范围尚未验证时，相关任务保持待准备，不能宣称主体保护已完成。普通去背景输出不能替代透明材质、强反光区域的专门验证。

### SR-006 方向选择、主参考与困难视角

每个物理场景提供两个文字方向，说明主要视觉变化、功能保持方式及跨视角处理思路。用户选择后，先制作该场景的代表帧样图。

样图应使用最能清楚说明功能空间、接触、透视和采光的原帧作为主要依据。自检通过且用户确认后，新场景样图成为主参考。原帧证据与新场景参考须分别标注。

原则上每场景使用一张主参考。新视角揭示重要区域、支撑结构或遮挡关系时，按需增加补充参考；同角度近景或普通姿态变化不必机械增加参考图。

明显多机位场景应优先验证新增区域最多或对应最困难的视角，通过后再扩展类似机位。单张正面样图通过不能证明侧面、背面及重要遮挡关系已经成立。

固定的是物理空间关系，不要求不同机位中窗户、台面始终处于画面同一侧。补充参考与共享设计冲突时先解决冲突，再继续传播。

### SR-007 内置 ImageGen 编辑与执行衔接

由 Agent 直接调用当前会话内置 ImageGen。每次请求明确区分当前原帧、场景设计与主参考、相关补充参考，以及核心保护和允许编辑要求。调用本地图片前应先查看对应素材。

用户指定名称为 imagegen2；当前工具接口未提供显式模型版本选择、种子或硬掩膜控制。记录用户指定能力及实际执行工具，模型版本、种子等仅记录实际返回的信息。提示词或参考掩膜图片不构成硬区域锁定保证。

每次扩展均使用自身原帧约束及固定场景设计，不仅依赖上一张生成图片。更换图片模型或调用路径须遵循用户选择，不能自动转用仓库同名旧 `image_gen` 或其他外部 API。

Python 工具准备并保存编辑请求；Agent 调用内置工具后，将结果导入项目工作区并提交对应记录；Python 核验来源、文件、引用和内容哈希。不得假设独立 Python 进程能直接调用 Agent 会话工具。

生成候选、最终合成图、提示词、参考素材和执行结果分别保存。项目引用的素材必须复制或保存到项目目录，不仅存在于会话默认输出位置。

### SR-008 候选接收、构图对应与受控合成

生成结果进入合成前，必须通过接收检查：

- 图片可保存、可解码，方向、尺寸及颜色信息可识别。
- 能确认它对应当前编辑请求、原帧与参考版本。
- 构图能与原帧工作画布建立可靠对应，承载、接触及主要透视关系可成立。

尺寸相同不代表构图相同，简单 resize 也不能作为构图对应通过的依据。

以原帧的无损工作基准、画布和主体坐标作为固定基准。允许对候选背景进行必要尺寸处理或对应调整，并记录处理；不得为迁就候选图而移动、缩放或形变原主体。无法可靠对应时退回候选图返工，不强行回贴放行。

在已确认区域采用生成内容、完成必要光学适配并恢复原图可靠核心后，检查双轮廓、额外肢体、旧背景残留、错误遮挡和接触位置。

核心像素检查使用既定工作基准及无损最终图，不以 JPEG 预览作为比较基准。先验证保护范围完整，再检查已确认核心的像素一致性，防止掩膜漏保护而像素检查仍通过。

### SR-009 采光与复杂材质

新环境的采光方向、明暗关系及自然光条件须与锁定主体兼容。冲突时调整环境，不对产品或人物核心做整体曝光、白平衡或色温调整。

孔洞、玻璃、强反光金属和接触阴影分别处理。玻璃的透射、反射与自身细节不能混同于普通背景孔洞；金属环境映像可以在已确认范围适配，但标识、接缝和控制件仍须保护。

光学区域应在编辑前检查并记录，之后的范围变化也须有依据和复检。不得以光学适配掩盖产品悬浮、承载高度错误或透视冲突。

分别记录不透明、孔洞、透明和强反光素材的验证结果。无法可靠分离需要保留与需要适配的信息时，当前帧保持待处理；分割选型或核心像素回贴本身不能证明复杂材质已经可用。

### SR-010 自检规则与问题证据

自检按以下时点进行：生成前检查输入与保护范围；生成后检查候选接收、环境结构和采光；合成后检查主体及融合；整组扩展后检查同场景关系与锚点覆盖。

程序负责尺寸、时间、哈希、版本和核心像素等确定性检查；Agent 对照原图、约束及确认参考，查看整图和必要局部放大图，判断空间、融合、差异和跨视角关系。

每项检查记录为通过、不通过或待确认；确实不适用时注明原因。每个问题至少包含规则、相关帧和区域、证据、可能原因、返工动作、影响范围及预期改善。原因不确定时记录待调查，不虚构确定诊断。

主体保持、功能空间、显著差异和同场景一致性属于硬要求，不能被综合评分抵消。缺少证据不能视为通过；不影响硬要求的轻微美观问题可以作为建议保留。

### SR-011 自检与返工映射

| 检查项 | 不通过时的优先处理 |
| --- | --- |
| 输入、PTS、场景或参考版本错误 | 修正输入与引用，重新准备受影响请求 |
| 结果不能解码或构图无法可靠对应 | 核对执行结果；构图错误则重做候选环境，不移动原主体 |
| 主体或必要部件漏保护 | 修正区域划分，重新检查并合成 |
| 核心像素、原色或亮度变化 | 检查尺寸、颜色处理、羽化与回贴，恢复原核心 |
| 孔洞、透明区或环境反射错误 | 按材质修复允许区域，保留结构与材质细节 |
| 白边、旧背景、双轮廓或额外肢体 | 修复对应区域，重新合成并检查周边 |
| 承载、接触、遮挡或活动空间错误 | 修正环境几何与布局，之后再修阴影 |
| 机位或透视不相容 | 按原帧约束修正环境，必要时重做该帧候选 |
| 采光与主体冲突 | 调整环境光线与背景明暗 |
| 环境视觉差异不足 | 回到场景设计，增强主要背景特征 |
| 同场景结构冲突 | 判断单帧偏离或共享设计错误，修正后复查依赖 |
| 锚点不足以表达重要变化 | 先补观察证据，必要时通过上游增加编辑锚点 |

优先修复最上游原因与最小必要范围。每次 ImageGen 返回结果仍视为候选，局部修改请求也可能影响其他区域。

每轮返工后复检原问题、全部硬要求及受影响跨帧关系，确认此前合格内容没有被破坏。重复同一方法无改善时停止并重新诊断。

### SR-012 逻辑任务与自动返工上限

每张锚点对应一个逻辑编辑任务，记录原帧、锚点角色、已批准编辑目标及其历史。在首次编辑生成请求之外，最多再自动调用 ImageGen 返工两次；局部重绘同样计入。

返工计数归属于逻辑任务，不能因更换提示词、文件名、请求名、参考版本、修订号或恢复会话而清零。Agent 为同一目标主动重选原帧，也不能借此自动突破上限。

单纯本地修正、重新合成和复检不占 ImageGen 返工次数，但重复操作无改善时仍应重新诊断。调用结果未知时保存执行状态并核对已返回或已保存结果，不能直接假定失败后重复提交。

用户明确确认实质新输入或新设计目标时，可以另建逻辑任务，记录原因、与前任务的关联及新尝试范围。技术性请求变化不自动视为新任务。

达到上限后：

- 硬要求不通过或仍无法判断的图片保持待处理。
- 保留最佳候选、证据和剩余问题。
- 暂不作为已确认参考或下游视觉锚点。
- 无依赖的其他图片可以继续。
- 继续尝试、改变设计或调整要求须形成新的明确决定。

本阶段采用专用规则：**自动返工上限不降低验收要求**。该规则优先于通用 reviewer 的“两轮后带警告放行”处理，但不改变其他无关阶段的评审政策。

### SR-013 版本、依赖与恢复

场景设计、参考图、保护范围、编辑请求、自检和用户确认绑定具体版本。新候选不覆盖历史，当前采用结果不自动等于最新生成结果。

每完成一步保存进度。恢复时先检查已有结果：已生成未自检则继续自检；已记录返工方案则继续对应任务；输入和依赖未变且结果有效时，复用结果和已有确认。

迟到的旧请求结果保留为历史候选，不能覆盖当前采用版本。资产引用和检查提交须匹配对应请求及输入哈希。

| 变化 | 处理要求 |
| --- | --- |
| 上游重新选择原代表帧 | 对应旧帧保护范围、合成结果及帧级验收不能直接套用；历史保留 |
| 场景主参考或补充参考变化 | 核验适用范围，相关依赖帧进入待复检 |
| 共享布局或采光规则变化 | 复查所有受该规则影响的帧，包括未直接引用修改图片的帧 |
| 单帧局部边缘修正 | 复检该帧及实际依赖该结果的内容 |
| 上游修订号变化但实际输入与依赖未变 | 经核验可保留有效结果，不一律重做 |

待复检不等于重新生成。已有图片仍满足当前设计时可继续采用，并保存复用依据及有效的检查/确认关联。当前设计发生实质变化时，沿用场景方向、样图及组级确认流程。

### SR-014 职责与下游衔接

Agent 负责场景理解、分组、方向设计、参考选择、内置 ImageGen 调用、视觉审阅和返工决策。Python 负责分割能力接入、素材处理、保护范围修正结果接收、受控合成、确定性检查及记录保存。

场景替换流程由项目流水线约定和 Agent 技能承载；本 PRD 不要求新增通用 Python 编排器。生产运行仍需准备可用工具、明确样图与扩组范围，并记录用户的实际确认。

场景替换通过只表示本阶段资产验收通过。具体视频模型另行选型，后续须检查输入角色、数量、时间语义、媒体规格及接入能力，不能将本阶段通过等同于所有视频模型均可直接消费。

完整保留锚点和用途。适配超出模型能力时明确报出问题，不能静默丢弃必要锚点或改变时间。后续人物替换及视频阶段的结果须有各自验收，不能由本阶段静态图片自检替代。

## 5. 验收标准

| 编号 | 验收场景 | 预期结果 |
| --- | --- | --- |
| SR-AC-001 | 同一厨房在视频中间隔出现 | 能归入同一物理场景并共享设计，保留原时间顺序 |
| SR-AC-002 | 正面和侧面分别展示产品承载结构 | 两个视角功能成立，主要空间关系一致 |
| SR-AC-003 | 保护范围漏掉部件或误填把手孔洞 | 可定位、提交修正并重新检查；不能仅靠核心像素一致通过 |
| SR-AC-004 | 图片尺寸相同但主体或台面位置偏移 | 构图对应检查识别问题，不移动原主体强行合成 |
| SR-AC-005 | 候选图改变产品颜色或亮度 | 最终核心恢复原像素、原色和原亮度后才可通过 |
| SR-AC-006 | 玻璃或金属中残留旧环境 | 在已确认光学区域处理；无法可靠分离时待处理 |
| SR-AC-007 | 局部返工引入额外手指、双轮廓或错误遮挡 | 复检发现新增问题，保留此前有效候选 |
| SR-AC-008 | 环境采光与主体明显冲突 | 调整新环境，不能整体调色主体核心来迁就背景 |
| SR-AC-009 | 更换后只有轻微调色或少量摆件差异 | 差异性检查不通过，回到环境设计 |
| SR-AC-010 | 存在新增区域较多的困难视角 | 在整组扩展前验证该视角，冲突未解决不继续传播 |
| SR-AC-011 | 主参考共享布局被修改 | 相关帧进入待复检，未受影响结果可核验复用 |
| SR-AC-012 | 两次自动返工后仍有空间错误 | 保持待处理，不交付下游或作为确认参考 |
| SR-AC-013 | 更换请求、参考版本或恢复会话 | 同一逻辑任务计数不清零，未知调用结果不盲目重试 |
| SR-AC-014 | 用户确认实质新设计 | 新建有关联记录的任务，保留旧目标与失败历史 |
| SR-AC-015 | 生成后中断，或旧请求结果迟到 | 复用已保存结果继续检查，旧结果不覆盖当前采用版本 |
| SR-AC-016 | 第一阶段更换代表帧 | 重查该帧依赖，保留历史与无关有效结果 |
| SR-AC-017 | 整组交付 | 每张图可追溯到原帧、场景设计、保护范围及有效验收/确认 |
| SR-AC-018 | 静态图片通过但视频模型尚未适配 | 保留本阶段通过和后续适配待验证的区别，不承诺视频效果 |

## 6. 可行性验证与暂缓事项

### 6.1 当前评估

总体路线条件可行。主体可靠核心的像素回贴可采用确定性图像处理实现，但保护范围可靠性、透明/反光信息分离、生成构图对应及跨视角扩展效果尚需真实样例验证。

现有去背景工具不等于已经具备保护范围修正与受控合成；当前会话内置 ImageGen 不等于仓库中的旧同名接口。应先验证请求准备、内置调用、结果导入、构图检查、合成、自检和恢复的完整链路。

本稿落盘依据静态代码审查与接口核验，尚未进行真实图片生成、合成或性能实测。技术目标不能表述为已经达到的生产成功率。

### 6.2 首版技术验证矩阵

| 验证类型 | 重点 |
| --- | --- |
| 不透明产品与承载面 | 固定画布回贴、核心保持、构图对应及接触成立 |
| 孔洞和细部件 | 背景透过区域、保护完整性及修正接口 |
| 玻璃与强反光金属 | 核心和光学区域能否可靠划分，材质与细节是否保留 |
| 手部接触与遮挡 | 原有可见顺序、局部修复及新增缺陷检查 |
| 同场景机位差异最大的样例 | 主参考对困难视角的约束能力，之后再扩展相似视角 |
| 重选帧、参考改版、中断与迟到结果 | 依赖失效范围、结果复用及逻辑任务计数 |

验证须记录实际工具、素材类别、原始请求与各轮结果、首次通过情况、两轮后结果、人工介入、耗时及失败原因。记录能核实的资源或费用信息；未知信息标记未知，不将其填为零或承诺值。

样例用于确认可处理范围和失败类型，不能由单个不透明产品样例推断复杂材质全部可用。尚未验证的类别保留待验证标识；生产中的具体图片仍逐项检查，未满足硬要求则不交付。

### 6.3 暂缓选型及后续边界

分割模型、修正算法的具体实现及其资源耗时另行评测；具体视频模型、动作与时序保真度在后续阶段确定。

首版不承诺严格三维一致性、ImageGen 硬区域锁定、固定模型版本或确定性生成。能力不足时按既定失败路径处理，不改变本版主体和空间验收要求。

### 6.4 非首帧路径的接口依据

2026-09-05 的接口复核显示，Runway 官方 SDK 的视频编辑接口支持以输入视频中的秒数或相对位置绑定指导图片，并对图片数量设置上限。这仅证明非首帧视觉锚点存在可选接入路径，不构成本项目已经接入、选定该模型或验证视频保真效果的结论。[Runway 官方 SDK](https://github.com/runwayml/sdk-python/blob/main/src/runwayml/types/video_to_video_create_params.py)

具体模型适配时应重新核验当时的官方接口和项目工具契约；不得把静态场景替换验收当作视频生成可行性的最终证明。
