# TikTok 短视频复刻 Phase 2 PRD：场景直出替换 V2.1

## 1. 目标

以 Phase 1 已锁定的关键帧为输入，让当前会话内置 `image_gen` 直接生成完整
新场景图。V2 不制作蒙版、不分离背景、不恢复源像素、不做合成。大模型在每次
生成后执行多模态自检，并按缺陷严重度决定局部调整或从源关键帧重新生成。

最终产物是可审计的静态关键帧包，不包含视频生成、人物替换、音频处理或成片
拼接。

## 2. 受众与场景真实性

所有场景面向北美 TikTok 带货消费人群，核心年龄为 30–50 岁。环境必须符合
产品真实用途、北美生活方式和消费习惯，优先采用普通消费者可能拥有、租用、
进入或日常使用的场所。

场景可以整洁，但应保留可信的空间尺度、收纳、磨损、自然光或家居照明、实用
物件与安全条件。禁止默认使用广告摄影棚、无缝背景、展厅式对称、奢华样板间、
夸张英雄光、无使用逻辑的道具阵列或不现实的商业测试场。

每个物理场景必须提供恰好 3 个不同方向。每个方向都要说明：

- 可见环境变化；
- 功能与操作空间如何保留；
- 跨视角一致性策略；
- 普通消费者拥有或进入该场所的合理性；
- 30–50 岁目标人群的真实使用习惯；
- 至少两个真实性线索；
- 明确的反棚拍约束。

用户必须看到三个方向并明确选择；系统不得代替用户确认。

## 3. 主体保真要求

V2 采用严格的视觉/语义保真，而非逐像素复制。对比源关键帧，产品或人物的
身份、轮廓、形状、比例、颜色、材质、标签和文字、零件、控制件、附件、姿态、
画面位置、遮挡、接触关系和交互状态必须保持不变。

新增或丢失部件、重复产品、人物肢体畸变、产品重设计、主体漂浮、支撑关系
错误、位置或比例明显变化均不得通过。新环境必须发生足够明显的结构或材质变化，
但不能改变主体正在执行的动作和功能。

## 4. 精确 Prompt 与生成握手

系统根据已确认的场景方向、锚点约束和返修原因构建最终 prompt，调用方不得覆盖
目标、prompt 或参考图拓扑。每次请求必须保存并输出传给模型的完整 prompt 原文及其 UTF-8 SHA-256。输出还
必须包含按顺序排列的参考图、每张图的角色与用途、生成模式、尝试次数、请求 ID、
请求能力 `imagegen2` 和实际工具要求 `image_gen`。
每条 prompt 必须明确要求生成 `720x1280`、`9:16` 竖图。

固定顺序为：

`prepare_edit → Agent 查看并输出返回的精确 prompt → apply_review(pre_generation) → mark_dispatched → 内置 image_gen → import_result/reconcile_execution → apply_review(generated_result)`

`mark_dispatched` 只能在当前请求的预生成审核通过后调用，并必须紧邻真实的
`image_gen` 调用。Python 不调用生成服务，也不代替大模型做视觉判断。

## 5. 三种生成模式

### 5.1 initial

逻辑任务的首次生成。从源关键帧作为 `edit_target` 出发，场景设计作为
`design_record`。扩展帧还需引用已通过的主样本作为 `continuity_reference`。

### 5.2 local_adjustment

仅当所有问题的最高严重度为 `minor`，且没有硬规则失败时允许。当前已生成图是
`edit_target`，源关键帧作为独立 `invariant_reference`。Prompt 只修复已诊断的
局部缺陷，同时重复全部主体保真约束。

### 5.3 source_regeneration

任何 `major`、`critical` 或任一硬规则失败都必须使用。从源关键帧重新作为
`edit_target` 生成，失败图不得进入参考列表，避免继承其结构错误。Prompt 必须
针对具体原因修改，不能只写“重试”。

硬规则包括主体与产品保真、构图对应、功能空间、接触、遮挡、透视、光照、环境
差异、跨视角一致性、北美语境、目标人群适配、真实消费环境和非棚拍审美。

最高严重度决定路由。每个问题必须记录规则、锚点、区域、证据、观测失败、可能
原因、具体返修动作、影响范围和预期改善。

## 6. 调用次数与执行恢复

每个逻辑锚点任务最多 3 次计数调用：首次生成 1 次，加最多 2 次返修。Prompt、
文件名、参考顺序、会话恢复或模型返回信息变化均不能重置计数。执行状态未知时，
必须先 `reconcile_execution`，不得继续调用。

确认未执行的调用可以退回计数；确认失败的调用仍计数；迟到结果保留为历史但
不能自动成为当前结果。

## 7. 图像导入边界

模型输出必须为完整、不透明、可解码图像。目标画布固定为 `720x1280`。以
`abs((生成宽/生成高)/(720/1280)-1)` 计算相对宽高比差异：

- 返回图已经是 `720x1280` 时保持原样；
- 宽高比差异不超过 5%（含边界）时，对整张图做 Lanczos 缩放，归一化为精确
  `720x1280`。

禁止裁切、补边、蒙版、抠图、主体像素恢复或合成。仅上述 5% 容差内允许两轴存在
轻微不同的缩放比例；超过 5% 时结果进入阻断状态，需要自检与返修。

## 8. 审核与人工闸门

生成模型必须先查看源图、直出图、源/结果对比图和重点区域裁剪，再提交完整
`generated_result` 自检。通过后系统才记录采用结果。

模型自检不能替代人工闸门：每个物理场景的主样本通过后需用户确认；全部锚点
通过后，先为每个物理场景生成带源图/结果配对和 `Sxx_Kxx` 标签的对比板并由用户
确认整组一致性。所有场景通过后，再生成一张覆盖全部关键帧、按片段与关键帧顺序
排列的总多帧对比图。用户必须对当前总图单独确认，发布确认不能替代该闸门。

## 9. 状态与交付

V2 写入：

- `artifacts/replication/scene-replacement-v2/`
- `assets/images/replication/scene-replacement-v2/`

旧蒙版/合成 V1 引擎、Schema 与公共操作从当前产品中删除，不再恢复或继续执行。
已有直出 V2.0 状态在下一次写操作时以不可变新 revision 升级为 V2.1。

交付仅包含依赖仍然有效、模型自检通过、人工样本和分组确认通过的直出图。每张图
必须追溯到源锚点、源时间、场景方向、精确 prompt 与哈希、生成模式、最多三次的
尝试历史、请求/结果/审核 ID 和人工确认。片段使用 `S01.mp4`、`S02.mp4` 等顺序名，
关键帧使用 `S01_K01.png`、`S01_K02.png` 等归属名，同时保留内部稳定 ID。交付必须
绑定总对比图、格位映射和最终人工确认。下游视频适配默认仍为 `unverified`。

## 10. 验收标准

- 无公开蒙版或合成操作；
- 每个场景恰好 3 个方向；
- 场景契合北美 30–50 岁消费者真实使用环境，避免棚拍感；
- 每次生成前输出精确 prompt 与哈希；
- 大模型对每个结果完成全量自检；
- 严重度路由、参考图拓扑和三次调用上限由状态机强制执行；
- 每场景对比图与总多帧对比图均有哈希和格位绑定；
- 最终总图经用户明确确认后才能发布；
- 交付为 720x1280 直出图，使用可读顺序命名，并保留完整可验证谱系；
- 上述要求属于通用视频复刻流程，不绑定任何单一商品任务。
