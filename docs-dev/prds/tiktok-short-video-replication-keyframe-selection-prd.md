## 1. 背景、目标与需求优先级

现有第一阶段默认在原子片段起点附近寻找最早合格帧。这种方式能够避开部分黑场和模糊画面，但可能错过片段中更清楚展示产品、操作关系和功能空间的画面。

本次将默认策略调整为：

> 在整个原子片段内选择一张主代表帧；必要时补充编辑锚点，保留真实时间位置。

目标是提高视觉锚点的信息有效性，为后续场景替换提供可靠的主体、空间、透视和采光依据，同时控制需要编辑的图片数量。

本稿是 Phase 1 的增量需求基线。涉及选帧时，以本稿替代旧 PRD 及其上游原始需求中的“清晰近首帧”“最早合格即选中”“主起始关键帧”和“内部切换锚点”的相关表述。旧 PRD 保留为现有实现基线；尚未升级的输出必须继续标注其实际选帧策略。

镜头边界检测、强制切点、片段时长约束、重组、删除区间及音频导出继续遵循既有规则。允许清晰运动画面成为代表帧，不等于修改强制切点的低运动偏好。

### 1.1 本期范围

- 全区间候选准备、本地技术预筛与 Agent 语义选帧。
- 主代表帧、补充编辑锚点和观察帧的角色管理。
- 精确时间绑定、审核记录、重选修订及受影响结果的识别。
- 与现有边界审核、生成片段清单和媒体导出的兼容。

### 1.2 不在本期范围

- 场景或人物替换、视频生成模型调用及最终拼接。
- ASR、叙事边界识别、全量原尺寸帧存储库。
- 新增审核 UI、本地语义模型或分割模型选型。

输入沿用第一阶段支持的本地、可 seek、可解码 SDR 视频及对应预处理结果；不扩展 HDR、DRM 或多视频流编排能力。

## 2. 核心概念与流程

| 概念 | 定义 | 是否进入场景替换 |
| --- | --- | --- |
| 主代表帧 | 每个原子片段默认选择的一张、适合表达该片段关键视觉信息的原始画面 | 是 |
| 补充编辑锚点 | 主代表帧不足以约束重要视角、功能区域或产品状态时，额外指定的画面 | 是 |
| 观察帧 | 为理解动作、遮挡、空间或边界而查看的辅助画面 | 否，除非明确转为编辑锚点 |
| 场景主参考图 | 第二阶段确认的新场景图片，用于约束同场景外观与主要结构 | 由第二阶段产生 |

主代表帧不等同于首帧、剪辑切点或编码器关键帧。主代表帧数量按原子片段计算；一个生成片段可能包含多个成员的主代表帧。

处理流程：

**冻结原子时间区间 → 准备全区间候选与独立边界证据 → 本地技术预筛 → Agent 选择代表帧并判断补充需求 → 按已确定的生成片段关系绑定 → 输出带版本的选帧结果。**

边界审核和语义选帧使用各自的证据与提交，不互相等待。每个原子片段的代表帧选择不依赖第二阶段物理场景分组；第二阶段联合查看原帧后，再选择场景设计的主要依据。

## 3. 功能需求

### KF-001 全区间候选准备

候选范围为原子片段完整的 `[start_pts, end_pts)` 区间，取消原有前 1 秒、前 30% 搜索窗口和近起点优先规则。

候选应覆盖片段前、中、后部，并兼顾可观察到的机位、景别及产品状态变化。减少重复画面，同时保留短暂出现的有效操作信息。不得只取全局清晰度最高的若干帧而丢失时间和状态覆盖。

全区间参与技术分析，Agent 分批查看有限候选。发现信息缺口时，可以请求指定时间附近的观察帧。候选呈现数量、定向加采次数及同时驻留的图片数量应有有限、可配置的上限，并在报告中回显。

达到上限仍存在关键证据缺口时，记录已查看范围和未解决项，转为待处理，不以达到上限替代选帧完成。

### KF-002 本地技术预筛

本地工具计算清晰度、曝光、黑白场及重复程度等指标，排除明显不可用画面，并保存筛选原因。技术指标作为证据，不直接替代产品与操作信息判断。

- 画面运动量大，不等于画面不可用。
- 全图清晰度高，不等于产品细节清楚。
- 静止画面，不自动优于清晰的操作画面。

代表帧搜索、排序和运动帧取舍采用独立选帧策略，不能通过修改共用质量门槛意外改变强制切点。技术筛选不要求安装本地语义模型或分割模型。

### KF-003 主代表帧选择

每个具备可用画面的原子片段确定一张主代表帧。Agent 按以下优先关系判断：

1. 产品及关键部件是否清楚，操作点、接触关系和相关状态是否可辨。
2. 与当前展示有关的人物、手部及动作是否有足够信息。
3. 必要承载面、操作区域及其他功能空间是否可见。
4. 满足以上条件时，优先选择清晰度、曝光和环境覆盖更好的画面。

更广视野只有在增加有效信息时才构成优势，不能以牺牲产品可辨识度为代价。人物覆盖以当前展示需要为准，不要求每张图都出现完整人物。

选择结果须记录理由、相关候选证据和仍存在的信息缺口。用户的明确选择可覆盖 Agent 的选择，但须记录理由和修订关系，保留可见质量问题。

### KF-004 按需增加编辑锚点

以下情况可以增加补充编辑锚点：

- 新视角揭示主代表帧未覆盖的重要功能区域。
- 产品打开、展开、拆卸等状态变化需要明确控制。
- 重要接触或遮挡关系发生变化，单张代表帧无法充分表达。

每个补充锚点须说明它补充了什么信息、为什么需要进入编辑流程，以及其真实时间位置。

仅用于了解动作过程或背景的观察帧，不自动增加待编辑图片数量。同角度的普通姿态变化不必机械增加锚点。观察帧转为编辑锚点时，须显式记录角色变更和用途。

### KF-005 首帧与下游模型策略

默认不额外导出或编辑首帧。后续明确选择需要首帧输入的视频模型时，再按需补提、处理对应画面。

具体生成模型另行选型。本阶段不假定所有模型都支持任意时间位置的视觉锚点，也不把某一模型的图片数量上限作为所有任务的固定上限。

完整保留锚点和用途。后续适配具体模型时，必须检查输入角色、数量、时间语义和媒体规格；不能静默丢弃必要锚点、修改锚点时间，或把普通参考图冒充指定时间的控制帧。

### KF-006 时间与生成片段绑定

所有选定画面须保留真实源 PTS 和有理数时间基，并记录所属原子片段、原子片段内偏移、所属生成片段及其中的偏移。秒数仅为精确时间的派生展示值。

生成片段包含多个原子片段时，保留各成员的主代表帧及必要补充编辑锚点。代表帧真实位置与内部剪辑边界分别记录，不把第一张代表帧强行标为第 0 秒，也不把后续代表帧时间当作内部切换时间。

锚点必须来自所属区间内的真实可解码帧。不得使用平均帧率反推 VFR 视频中的权威时间，不得用其他片段的图片伪造连续性。

### KF-007 独立保留边界证据

自然边界审核继续使用边界两侧最近解码帧、附近上下文及其他既有证据。这些固定观察证据的准备不等待主代表帧语义确认。

主代表帧移到片段中部或末尾后，不能替代边界附近证据。重选主代表帧不自动替换已经审核的独立边界证据。

若某份既有边界审核实际引用了已更换的主代表帧，应重新核验受影响判断，并生成匹配新证据的请求。旧提交不得直接套用到不同哈希的审核请求。

### KF-008 审核状态与异常处理

明确区分“时间轴规划已就绪”和“视觉锚点已就绪”。片段合法不表示选帧已经通过审核；选帧待审不得删除已经成立的时间轴和有效边界审核记录。

时间轴是否允许媒体导出仍由其合法性及既有导出约束决定。第二阶段必须检查其实际消费的编辑锚点已就绪，不能仅凭旧版 `plan_status=ready` 推断素材均可使用。

正常情况下由 Agent 完成选帧检查。以下情况进入待处理状态：

- 所有候选都有明显质量问题。
- 产品或关键操作持续被遮挡，无法形成可靠锚点。
- 没有可解码帧。
- 补充观察后仍无法判断，或达到加采上限仍缺少关键证据。

可以保留最佳候选供审阅，但必须标记问题，不能用综合分最高代替合格结论。用户确认的降级选择保留质量说明，第二阶段仍按自身硬要求验收。

### KF-009 重新选帧与修订

支持针对指定原子片段重新选择代表帧或调整补充锚点，并产生新的修订记录。

重新选帧应保留源时间区间、历史图片和历史选择，记录新旧结果关系及原因，标记受影响的下游保护范围、编辑结果与审核结论。仅修改选帧策略或提交时，不得连带改变冻结的原子边界；升级确需变更实体标识时保留明确映射。

选帧、边界判断、重组和媒体导出的依赖应分别核验。源文件、精确区间、流选择及编码参数未变时，经内容哈希与导出信息校验，复用已有视频资产，并更新其与当前锚点的关联；不得仅因修订号变化重复转码。

重选修订的资产复用属于新增能力，不能假定当前实现已有精细增量缓存。

### KF-010 职责、提交与兼容

Agent 负责语义选择、补充需求判断和视觉审核；Python 负责候选准备、媒体提取、技术指标、时间校验和记录持久化。

提供独立的选帧提交，按原子片段表达一张主代表帧和零到多张补充编辑锚点，并绑定候选证据与输入修订。观察帧保留在证据引用中。不得把选帧决策混入边界关系提交。

下游按图片角色读取锚点，校验每个已就绪原子片段恰有一张主代表帧，而非校验“所有图片数量等于成员原子片段数量”。

旧版近首帧结果保留原选帧策略标识。经新规则评估后可以继续采用同一帧，不能仅修改角色名称就视为完成新流程。变更后的数据契约须可识别版本；不支持新角色或多锚点的消费者应明确报出不兼容。

## 4. 输出与非功能要求

### 4.1 最小输出信息

| 信息类别 | 必须包含的内容 |
| --- | --- |
| 来源 | 源文件标识、上游修订、原子片段及生成片段关联 |
| 时间 | 源 PTS、时间基、原子片段内及生成片段内偏移 |
| 角色 | 主代表帧、补充编辑锚点或观察帧 |
| 素材 | 图片路径、尺寸、方向及内容哈希 |
| 决策 | 选择理由、补充用途、候选证据、技术指标、质量问题及审核状态 |
| 修订 | 选择提交、父修订、新旧结果关系及受影响依赖 |

输出选帧清单、带时间和角色标注的联系表、审核记录与修订关系。沿用项目规范入口消费结果，不扫描目录猜测当前版本；运行产物保存到 `projects/<project-id>/` 的标准目录。

### 4.2 无损工作基准与资源控制

用于后续编辑的原帧以原始解码画面建立无损工作基准，记录方向归一化及颜色处理，保持原帧有效内容与尺寸。预览联系表可以使用压缩图片，但不能成为主体像素检查基准。

原尺寸图片仅按选中或待核实 PTS 提取，限制同时驻留内存的图片数量。不得为实现全区间筛选而默认保存所有原尺寸解码帧。

候选、加采和资源上限须可配置并有明确默认值，在技术设计中结合样本确定后回显到结果。记录分析、提取及 Agent 审核的实际耗时，不在未实测时承诺固定处理速度。

### 4.3 可追溯性

相同输入、配置和同一审核提交应能够重建相同选择记录。不要求不同 Agent 独立作出完全相同的语义判断，也不要求跨解码器版本的图片字节完全相同。

基础运行沿用项目 Python 3.12+ 环境；技术预筛不依赖 GPU 或语义模型权重。

## 5. 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| KF-AC-001 | 产品在后半段才完整显露 | 可以选中后半段，不受近起点窗口限制 |
| KF-AC-002 | 远景更广但产品过小，中景能看清操作 | 优先满足产品与操作信息需要 |
| KF-AC-003 | 静止帧遮挡操作点，运动帧清晰展示操作 | 运动帧不会仅因运动量大被淘汰 |
| KF-AC-004 | 清晰操作只短暂出现 | 候选准备保留该有效状态，不被全局高清排序或去重全部过滤 |
| KF-AC-005 | 仅为理解动作补取观察帧 | 待编辑锚点数量不自动增加 |
| KF-AC-006 | 产品展开后出现需要控制的新结构 | 可增加用途和时间明确的补充编辑锚点 |
| KF-AC-007 | 所有候选均不可用，或加采上限后证据不足 | 输出问题与证据，保持待处理 |
| KF-AC-008 | 多个原子片段合并，且某成员有补充锚点 | 各锚点角色与偏移准确，内部切点独立保存 |
| KF-AC-009 | VFR、非零起始 PTS、旋转视频、接近排除边界的画面 | 源帧定位和两级时间映射准确，锚点不越界 |
| KF-AC-010 | 主代表帧待审或移至片段末尾 | 独立边界证据完整，已成立的时间轴与边界审核仍可保留 |
| KF-AC-011 | 仅改变代表帧搜索或运动帧取舍策略 | 强制切点及冻结原子区间不因共用配置被改变 |
| KF-AC-012 | 针对一张代表帧重选 | 新修订可追溯，受影响下游被标记，其他有效结果可保留 |
| KF-AC-013 | 重选后源区间与导出参数完全相同 | 经校验复用已有视频路径及内容，不再次转码 |
| KF-AC-014 | 旧版近首帧包或旧版单帧消费者 | 识别实际策略与契约版本，不误标已审核或静默丢锚点 |
| KF-AC-015 | 具体视频模型不支持当前锚点数量或时间角色 | 保留完整锚点并报告适配问题，不静默改时间或删必要锚点 |

验收包含确定性的时间、引用、修订和兼容检查，以及预设样例的视觉评审。样例至少覆盖中后段显露产品、短暂清晰操作和明显运镜；记录候选数量、加采、耗时、人工介入与失败原因。

不得用“清晰度提高”单项代替代表性改善，不以未经验证的自动选帧准确率作为发布承诺。

## 6. 与既有需求的衔接及可行性结论

| 既有条款 | 本稿处理 |
| --- | --- |
| Phase 1 §2.1、FR-005 近首帧目标与搜索窗口 | 由 KF-001～KF-003 的全区间代表帧选择替代 |
| Phase 1 FR-004 强制切点 | 保留原目标，与代表帧取舍策略解耦 |
| Phase 1 FR-006 边界证据与审核 | 按 KF-007、KF-008 保留独立证据及审核依赖 |
| Phase 1 FR-009 主起始关键帧、内部切换锚点 | 按 KF-004、KF-006、KF-010 分离图片角色与剪辑边界 |
| Phase 1 FR-011、§7 输出与修订 | 增加角色、选择提交、锚点状态及选帧修订的资产复用 |
| Phase 1 §11 后续接口 | 按 KF-005 明确模型输入适配，衔接场景替换首版 |

静态复核结论：技术路径明确，现有逐帧小尺寸指标和精确 PTS 链路可作为基础。需要新增语义选帧提交、有限候选展示、多锚点契约以及选帧与切分/导出的解耦，不能视为仅扩大搜索窗口。

首版已实现上述工具链，并通过自动化测试检查时间映射、独立审核、旧包升级、无损工作图和视频资产复用。真实产品素材上的语义代表性、人工介入及生产耗时仍待样例评估；自动化测试结果不替代这部分效果结论。具体实现与验证命令见[实施设计与验收记录](../plans/tiktok-short-video-replication-keyframe-selection-plan.md)。
